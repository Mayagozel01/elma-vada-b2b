## Как работает поле

- В `templates/product.json` используется секция **Product details**. Поле находится внутри `{% form 'product' %}`, перед **Add to cart**. **Engraving details** остаётся информационным блоком.
- Сохранён существующий механизм: **Allow engraving text field** в настройках секции + `custom.personalization_enabled = true` у конкретного товара. В локальных файлах тегового механизма нет. Значения метаполей и теги действующего каталога не запрашивались: экспорт темы не содержит эти данные.
- Существующие `personalization_label` и общий `personalization_limit` удалены из схемы и шаблона. Подпись — **Engraving text**. Обязательность и максимальная длина задаются только у товара. Без положительного лимита поле не получает ограничения от темы.
- Обычный POST формы передаёт `id`, `quantity`, `properties[Engraving text]` и все остальные поля/свойства. AJAX-перехватчика добавления в этой теме нет. JavaScript проверяет поле, но не собирает новый объект свойств и не заменяет отправку формы. [Документация Shopify: line item properties](https://shopify.dev/docs/storefronts/themes/architecture/templates/product/overview#the-product-form).
- Required не принимает только пробелы. При превышении лимита показывается английское сообщение; вставленный текст не обрезается. Лимит считается в единицах UTF-16, как HTML `maxlength`: некоторые emoji занимают две единицы. Без JavaScript работают native `required`/`maxlength`; для выбора другого варианта предусмотрены ссылки с перезагрузкой страницы. Проверки темы выполняются на стороне клиента, а не как серверное правило Shopify.
- При смене варианта с JavaScript надпись сохраняется в поле. Вариант без гравировки скрывает и отключает поле, снимает обязательность и исключает свойство из POST. При переключении обратно восстанавливается введённая надпись. Отдельное локальное хранилище персональных надписей не создаётся; перезагрузка самой страницы товара не гарантирует сохранения черновика.
- Если количество больше одного, надпись относится ко всем единицам позиции. Пояснение есть у поля и в корзине. Для разных имён сохранена существующая ссылка **Request a Bulk Quote** и существующая Shopify Forms; её конфигурация не менялась.
- В теме используется страница `templates/cart.liquid`; выдвижной/AJAX-корзины в локальных файлах нет. Все публичные свойства выводятся с `escape`, длинные строки переносятся. Количество обновляется нативным массивом `updates[]` в порядке строк корзины; удаление использует `item.url_to_remove`. При обновлении не отправляется новый объект `properties`, поэтому остальные свойства не перезаписываются. Разделение одинакового варианта с разными свойствами — поведение Shopify, описанное в [документации корзины](https://shopify.dev/docs/storefronts/themes/architecture/templates/cart).

Цены, наличие, варианты, отзывы, главная страница, скидки, платная упаковка и дополнительные товары этой доработкой не изменяются.

## Включение на одном тестовом товаре — действия владельца позже

Сейчас выполнять эти действия в магазине не требуется: это инструкция для последующего согласованного теста в предпросмотре обновлённой неопубликованной темы. Метаполя принадлежат товару и общие для всех тем. Уже активная версия тоже использует `custom.personalization_enabled`: включение метаполя может показать её старое поле на публичной странице товара. Для изолированного теста используйте согласованный тестовый товар; не включайте метаполе массово.

1. Откройте **Настройки → Метаполя и метаобъекты → Товары**. В некоторых версиях интерфейса раздел называется **Пользовательские данные**. Найдите существующие определения по точному namespace/key; не создавайте дубли. Для недостающих нажмите **Добавить определение**, задайте название, исправьте **Пространство имен и ключ**, выберите тип и сохраните. Альтернативный путь — **Товары → тестовый товар → Метаполя → Добавить определение**. [Инструкция Shopify на русском](https://help.shopify.com/ru/manual/custom-data/metafields/metafield-definitions/creating-custom-metafield-definitions).

| Название определения | Namespace | Key | Тип Shopify | Значение у тестового товара |
| --- | --- | --- | --- | --- |
| Поле гравировки включено | `custom` | `personalization_enabled` | Истина или ложь / True or false (`boolean`) | `true` / Истина. `false` или пусто скрывает поле. |
| Текст гравировки обязателен | `custom` | `personalization_required` | Истина или ложь (`boolean`) | Сначала `false`; для проверки обязательности — `true`. Пусто = необязательно. |
| Максимальная длина гравировки | `custom` | `personalization_max_length` | Целое число (`number_integer`), одно значение; проверка: минимум `0` | Оставить пустым до согласования допустимой длины для изделия. Положительное число `N` = максимум `N`; пусто/`0` = ограничения темы нет. |
| Значения варианта без гравировки | `custom` | `personalization_no_engraving_values` | Однострочный текст → Список значений (`list.single_line_text_field`) | Необязательно. Указать точное существующее значение опции, означающее отказ от гравировки, например `Plain finish`, **только если оно действительно означает отсутствие гравировки**. |
| Дополнительное пояснение гравировки | `custom` | `personalization_note` | Многострочный текст (`multi_line_text_field`) | Необязательно; существующее пояснение сохраняется. |

2. В **Товары → нужный тестовый товар → Метаполя** заполните значения только этого товара и нажмите **Сохранить**. Не меняйте цены и варианты. Тип `personalization_enabled` должен быть boolean, а не строкой `"true"`.
3. В редакторе **обновлённой неопубликованной темы** выберите **Товары → Товар по умолчанию → Product details**. Включите **Allow engraving text field**. Это настройка секции, а не действие **Добавить блок**. Откройте тестовый товар в предпросмотре этой темы.
4. Значения опций `No engraving`, `Without engraving`, `Unengraved`, `No personalization`, `Without personalization`, `Без гравировки` распознаются автоматически: совпадение целого значения опции без учёта регистра и крайних пробелов. Совпадение части названия товара/варианта не используется. Общие значения `None`, `No`, `Plain` автоматически не трактуются как отказ от гравировки. Для других формулировок используйте список из таблицы. В него вводят отдельное значение опции, а не полный заголовок `Black / No engraving`. Настоящие значения вариантов нужно сверить в Admin перед тестом.

## Ручная проверка в предпросмотре

1. На товаре с выключенным/пустым `personalization_enabled` поля нет. На тестовом товаре с `true` проверьте подпись, placeholder, helper, клавиатуру и фокус на телефоне.
2. При required = false добавьте товар с пустым полем. При required = true пустой текст и пробелы должны блокировать добавление с понятной ошибкой.
3. После согласования лимита `N` проверьте `N` и `N+1` символов, в том числе вставкой. При превышении JavaScript показывает ошибку и не обрезает текст. При пустом лимите нет старого общего ограничения 80 символов.
4. Введите `Anna`, смените цвет/вариант, проверьте сохранение текста и правильные variant/quantity. Если в товаре уже есть вариант без гравировки, переключитесь на него: поле скрыто, покупка возможна без надписи. При переключении обратно текст сохранён. Отдельно проверьте прямую ссылку на вариант без гравировки и выбор вариантов с отключённым JavaScript.
5. Добавьте одну и ту же ручку с тем же вариантом сначала с `Anna` (2 шт.), затем с `Bob` (1 шт.). Ожидаются две строки; возле первой должно быть пояснение про все 2 единицы. Другие публичные свойства должны остаться видны.
6. Измените количество только у одной строки и нажмите **Update cart**. Обновите страницу: обе надписи должны сохраниться. Удалите одну строку через **Remove**, убедитесь, что удалена нужная. Затем проверьте удаление через количество `0` и **Update cart**.
7. Проверьте `<>&"` в надписи: они должны отображаться как текст. Проверьте длинную строку без пробелов на ширине 320–390 px: она должна переноситься в корзине без горизонтального скролла. Для разных имён проверьте существующий **Request a Bulk Quote** без отправки заявки, если отправка отдельно не согласована.
8. До оформления покупки проверьте текст возле нужной позиции в checkout. Реальный тестовый заказ оформлять только по отдельному решению владельца; затем проверить свойство в позиции заказа. Сохранение в настоящем заказе в рамках этой работы **не проверялось**.
