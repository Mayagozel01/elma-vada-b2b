# Gift offers только в корзине и существующие скидки за количество

Обновлено 17 ноября 2026. Изменена только локальная тема. Загрузки, публикации и изменений Shopify Admin, товаров, приложений, форм или скидок не было. Изначальные правки пользователя в `assets/theme.css`, `config/settings_data.json` и `sections/header.liquid` сохранены. Архив от 16 ноября не пересобран и этих изменений не содержит.

## Исправление открытия — 18 ноября 2026

Подтверждена причина ошибки **We could not refresh gift offers**: общий helper в `assets/cart.js` отправлял `Accept: application/json` и для Ajax Cart API, и для `GET /cart?sections=cart-gift-offers`. На этом маршруте Shopify при таком Accept возвращает обычный JSON корзины вместо секций. `read()` искал HTML по ключу `cart-gift-offers`, не находил его и останавливал открытие.

Проверено публичными GET без изменения корзины или Admin на `https://elmavada.com/cart?sections=cart-gift-offers`:

| Accept | HTTP | Редиректы | Формат ответа |
| --- | --- | --- | --- |
| `application/json` | 200 | Нет | Обычная корзина: items, total_price, item_count; нет ключа секции |
| `*/*` | 200 | Нет | Верхнеуровневый `cart-gift-offers`: строка HTML с data-cart-form |
| `text/html` | 200 | Нет | Верхнеуровневый `cart-gift-offers`: строка HTML с data-cart-form |

Повторная последовательность `*/* → application/json → */*` в одной cookie-сессии дала тот же результат. Конечный URL не менялся. Content-Type ответа во всех случаях — `application/json; charset=utf-8`: по нему одному нельзя различить корзину и секции. Никакие токены/содержимое пользовательской корзины в отчёт не включены. Это проверка публичной темы с отдельной пустой сессией, не пользовательского preview.

ID соответствует `sections/cart-gift-offers.liquid`; файл существует локально, сервер успешно отдаёт его с правильным Accept. Он рендерит общий `cart-content`, поэтому менять ID/метаполя/совместимость не требуется.

Исправлено: только standalone-запрос секций использует `Accept: */*`; Ajax-записи и `/cart.js` сохраняют JSON-заголовки. URL сохраняет локализованный маршрут формы, текущие query-параметры (включая preview_theme_id/preview_key), same-origin cookies; устаревший section_id и fragment исключаются. Редиректы по-прежнему отклоняются, чтобы не принять другой ресурс за секцию.

Отдельный `?sections=…` возвращает `{ "cart-gift-offers": "HTML" }`. Bundled rendering при POST возвращает HTML внутри `response.sections`; этот код использует отдельный GET и не подменяет его bundled-ответом. Отсутствие ключа, null, пустая строка и HTML без структуры корзины вызывают ошибку даже при HTTP 200. Ошибка видна также при неудачном автоматическом открытии. Фиктивных карточек и обхода свежей проверки нет. `sessionStorage` записывается только после `showModal()` и проверки `dialog.open`. Форматы сверены с [Section Rendering API](https://shopify.dev/docs/api/ajax/section-rendering) и [Cart API / bundled rendering](https://shopify.dev/docs/api/ajax/reference/cart#bundled-section-rendering).

Новая регрессия: `NODE_PATH=/tmp/elma-gift-checks/node_modules node scripts/verify-cart-section-response.cjs`. Браузерный стенд теперь воспроизводит различие Accept и проверяет сохранение preview-параметра, вместо безусловного возврата HTML для любого запроса.

Результаты 18 ноября: PASS — новый тест формата ответа, существующие тесты офферов/корзины/персонализации; Chromium на 320/390/1440 px (авто/ручное открытие, закрытие и повтор, добавление, итог, счётчик, Maya/Anna). JS syntax и diff check — PASS. Theme Check без новых замечаний: прежние 1 ошибка и 16 предупреждений. В рамках исправления изменены только `assets/cart.js`, `assets/gift-offers.js`, `scripts/verify-gift-offers-browser.cjs`, эта документация; добавлен `scripts/verify-cart-section-response.cjs`. Стили и Liquid-файлы не менялись.

После отдельной загрузки: в Network проверить фактический URL с контекстом выбранной темы, Request Accept `*/*`, отсутствие редиректа и строковый HTML по верхнеуровневому ключу. В новой сессии проверить окно через 5 секунд; затем закрытие, View gift offers, повторное ручное открытие и отсутствие повторного автопоказа после reload. С реальным **Gift Box with Gold Ribbon ($7)** проверить добавление, суммы/скидки Shopify, счётчик и сохранность гравировки в cart/checkout. Локальные фикстуры не подтверждают реальную покупку. Shopify Forms, Admin и скидки не изменялись; тема не загружалась и не публиковалась.

## Текущий сценарий

- Только `/cart` и локализованные пути корзины. На странице товара офферы отключены независимо от прежнего `enable_product_gift_offers`; назначения `custom.gift_offers` сохранены. Гравировка, выбор вариантов и **Buy more, save more** продолжают работать.
- После списка позиций, перед итогом и Checkout, сразу выводится постоянный блок **Complete your gift** / **Selected to complement your order.** До трёх карточек, компактная сетка на компьютере и вертикальный список на телефоне. Кнопки дополнений используют вторичный стиль; Checkout остаётся основным действием. Перед блоком есть ссылка **View total & checkout** с текущим итогом для быстрого перехода к оформлению.
- У каждой карточки фото, название, цена за единицу Shopify, количество по умолчанию **1**, **Add to cart** и, при наличии связи, **Pairs with** с первой подходящей основной строкой. Порядок: основные строки корзины → список Gift offers. Повторы variant ID убираются; первые три подходящих предложения видны в обоих местах.
- **View gift offers** вручную открывает окно с теми же карточками. Автопоказ по умолчанию через **5 секунд после load**, только для непустой корзины с предложениями. Ключ `elma:gift-offers:seen:v1` записывается после успешного `showModal`, включая ручное открытие. Перезагрузка/возвращение не повторяют показ в этой сессии вкладки. При недоступном чтении или записи sessionStorage остаются блок и ручное открытие.
- Скрытая вкладка, другой видимый native/ARIA-диалог, обновление корзины, несохранённые количества и начало Checkout запрещают отложенное открытие. Условия проверяются до и после свежего GET. Пропущенный таймер на этой странице не запускается заново; факт показа не записывается. Checkout не ждёт проверки офферов и остаётся нативным POST.
- Крестик, Escape и **Continue to cart** закрывают окно; блок остаётся, если есть доступные предложения. Фокус ограничен диалогом, возвращается к исходному элементу или доступному действию корзины. Фон фиксируется с сохранением позиции, тело окна прокручивается внутри, закрытие и Continue остаются видимыми.
- Несколько дополнений добавляются последовательно, каждое своей кнопкой. Окно после добавления остаётся открытым. **Adding…** защищает запрос от повторных нажатий; **Added ✓** появляется только после подтверждённого ответа и обновления корзины. Количество/статус синхронны в блоке и окне. Добавленные карточки можно видеть до закрытия окна; повторное добавление заблокировано, количество меняют в строке корзины.
- При ошибке показано сообщение на английском. Сначала выполняется чтение актуальной корзины, затем разрешается повтор. Если вариант фактически уже появился после неполного/неизвестного ответа, повтор не предлагается (в открытом окне — **In cart**, без ложного Added). Если чтение тоже недоступно, **Refresh cart** повторяет только GET; после восстановления связи можно продолжить без перезагрузки.
- Коробка исключается только для подходящих строк с коробкой, остальные дополнения остаются. Явное `false` варианта имеет приоритет над значением товара; пустое поле наследует его. Если оба поля пусты, совместимость коробки неизвестна и она не предлагается. Смешанная корзина может предложить коробку для строки без коробки.
- Уже имеющиеся варианты, выключенные/недоступные офферы, предложения без фото и варианты с неподходящей персонализацией/подпиской/минимальным количеством скрыты. Дополнения не порождают офферы. Пустая корзина или отсутствие предложений скрывают блок и не запускают таймер.

## Модель данных

Общий каталог — небольшой метаобъект **Gift offer**. Он содержит ссылку на реальный вариант Shopify и настройки показа, но не собственную цену. Одну запись можно выбирать у нескольких основных товаров и менять централизованно. Список ссылок у товара определяет порядок. Отдельная админка и приложение для офферов не нужны.

Одних ссылок на товары недостаточно для выбора конкретного продаваемого варианта. Вариант как единственный объект оффера потребовал бы размещать редакционные настройки каждого предложения на вариантах. Метаобъект оставляет каталог предложений в **Content → Metaobjects**, а склад и цену — у продаваемого варианта. Используются стандартные [типы данных Shopify](https://shopify.dev/docs/apps/build/metafields/list-of-data-types) и [списки ссылок](https://help.shopify.com/en/manual/custom-data/metafields/metafield-definitions/metafield-lists).

### 1. Метаобъект Gift offer

В **Settings → Custom data → Metaobjects → Add definition** создать тип `elma_gift_offer`. Включить доступ для витрины; если используется возможность Draft/Active, публиковать только готовые записи. Создание отдельных веб-страниц для записей не требуется.

| Ключ поля | Тип | Настройка / источник |
| --- | --- | --- |
| `title` | `single_line_text_field` | Название предложения, например согласованное название коробки; использовать как display name. Пустое значение имеет fallback на название товара. |
| `variant` | `variant_reference` | Обязательная ссылка на конкретный продаваемый вариант. Выбирать через Shopify picker, не вводить ID в код темы. |
| `image` | `file_reference`, только изображения | Необязательное фото оффера; fallback: фото варианта, затем товара. При отсутствии всех фото оффер скрыт. |
| `enabled` | `boolean` | Только `true` разрешает предложение. Пустое/false скрывает его у всех товаров. |
| `kind` | `single_line_text_field`, choices | Только `gift_box` или `other`. Пустое/неизвестное значение скрывает оффер. |

**Поля цены нет.** На витрине выводится `offer.variant.value.price | money`, а покупка идёт через `/cart/add.js` с настоящим variant ID. JavaScript не передаёт цену. Налоги, скидки и итоговые суммы остаются за Shopify. Поле `_elma_gift_offer` — скрытая метка роли строки, не доплата и не источник права на скидку.

### 2. Метаполя товаров и вариантов

Создать определения в **Settings → Custom data → Products / Variants** с доступом для витрины.

| Владелец | Namespace/key | Тип | Назначение |
| --- | --- | --- | --- |
| Product | `custom.gift_offers` | `list.metaobject_reference` → `elma_gift_offer` | Выбрать несколько общих офферов. Порядок значений — порядок офферов для этой строки корзины. Для начала держать список компактным. |
| Product | `custom.includes_gift_box` | `boolean` | Необязательный общий ответ для всех комплектаций товара. |
| Variant | `custom.includes_gift_box` | `boolean` | Приоритет над значением товара. `true` — коробка входит; `false` — не входит. Если оба значения не заполнены, коробка не предлагается. Нельзя определять комплектацию по словам в названии. |
| Variant | `custom.is_gift_addon` | `boolean` | У продаваемого варианта дополнения обязательно `true`, иначе быстрый оффер скрыт. Такой вариант не считается основным при подсчёте количества и не порождает дальнейшие офферы. |
| Variant | `custom.requires_personalization` | `boolean` | `true` исключает вариант из быстрого добавления при любых прочих настройках. Использовать для сценариев, ещё не описанных текущими полями гравировки. |
| Product | `custom.volume_profile` | `metaobject_reference` → `elma_volume_profile` | Один общий профиль скидок; несколько товаров могут ссылаться на одну запись. |

Существующие `custom.personalization_enabled`, `personalization_required`, `personalization_max_length`, `personalization_no_engraving_values` не переименовывать. Дополнение с включённой или обязательной персонализацией исключается, кроме явно распознанного существующим механизмом варианта **No engraving**. `custom.requires_personalization = true` исключает его и в этом случае. Быстрое добавление начинается с 1, поэтому варианты с quantity_rule.min > 1 или max = 0 исключены. Для остальных действуют реальные step/max Shopify. Перед включением оффера проверить, что для него не нужны другие обязательные поля, загрузки, планы подписки или отдельная настройка комплекта. Продукты с обязательной подпиской исключены.

Для первой коробки: выбрать/подготовить настоящий товар, цену, фото, склад, доставку и продаваемый вариант, опубликованный в Online Store и нужных рынках. У варианта поставить `is_gift_addon = true`. Создать одну запись `Gift offer` с `kind = gift_box`. Подключить её через `custom.gift_offers` к нужным основным товарам и явно заполнить сведения о комплектации. Все эти действия — будущий этап, сейчас ничего не создано.

Для второй ручки или другого дополнения применяется тот же каталог. Если ручка должна также продаваться как основной товар со скидкой, использовать **отдельный реальный вариант/товар для роли дополнения**: один и тот же variant ID нельзя надёжно считать то основным, то дополнением только по изменяемому свойству браузера. Согласовать складской учёт. Пока у дополнения нужна гравировка, быстрый оффер останется скрытым; отдельный сценарий персонализации потребуется позже.

### 3. Метаобъект Volume profile

Создать тип `elma_volume_profile`, разрешить доступ для витрины. Поля:

| Ключ | Тип | Назначение |
| --- | --- | --- |
| `title` | `single_line_text_field` | Название профиля для выбора в Admin; display name. |
| `enabled` | `boolean` | Оставить false до настройки и проверки настоящих скидок. Это переключатель отображения, он не активирует скидку Shopify. |
| `tiers` | `json` | Массив объектов с ключами `minimum` и `percent_off`. Пока нет утверждения — `[]`. |

У `minimum` должно быть положительное целое число; у `percent_off` — число больше 0 и меньше 100. Пороги и проценты должны строго возрастать. Строки вместо чисел, пустой массив, некорректный порядок или значения скрывают весь блок. Реальных или демонстрационных порогов в тему не встроено. Процентный профиль выбран, чтобы разные цены вариантов и валюты не требовали ручных таблиц фиксированных сумм.

Подсчёт: сумма количеств строк **одного product ID** с любой гравировкой и основными вариантами этого товара. `Maya × 1` + `Anna × 2` дают 3 единицы, но остаются двумя строками. Другой товар с тем же профилем начинает свой подсчёт отдельно. Варианты `is_gift_addon = true` и строки с `_elma_gift_offer = true` исключаются. На странице товара подсвечивается порог для уже имеющегося количества плюс вводимое количество. Это подсказка по снимку корзины при загрузке страницы; она не подтверждает скидку и не меняет цены.

## Реальное применение скидок — следующий этап

Справка проверена по официальной документации 15 ноября 2026. Тариф и действующие скидки конкретного магазина не запрашивались.

1. **Небольшой набор товаров и порогов:** можно использовать автоматические **Amount off products → Percentage**, отдельную скидку на каждый порог одного основного товара, с **Minimum quantity of items**. Только выбранные товары/варианты должны входить в подсчёт. Не объединять разные основные товары в одну область действия, если порог должен считаться по каждому product ID отдельно. Добавляемые коробки и другие дополнительные варианты исключить. Это кандидат для простого запуска, который нужно проверить на двух строках с разной гравировкой. [Минимальные требования и области действия](https://help.shopify.com/en/manual/discounts/discount-types/percentage-fixed-amount).

2. Пороговые скидки одного товара не должны складываться на одной строке. Для разных товаров и других текущих скидок отдельно согласовать правила сочетания и проверить выбор лучшей скидки. Shopify допускает **до 25 активных автоматических скидок**, включая приложения; схема «товары × пороги» быстро расходует лимит. Не менять существующие скидки ради освобождения лимита автоматически. [Сочетание и лимиты скидок](https://help.shopify.com/en/manual/discounts/discount-combinations).

3. **Много товаров, общий профиль и независимый подсчёт каждого товара:** предпочтительна одна скидка приложения на **Discount Function API**. Алгоритм: прочитать cart lines, product/variant IDs и серверные признаки дополнений; сгруппировать только основные строки по product ID; выбрать максимальный достигнутый порог профиля; применить процент ко всем подходящим cart line IDs этого товара. Не изменять и не объединять строки с надписями. При уменьшении количества Shopify должен пересчитать скидку. Function работает в серверном расчёте; тема этого сделать не может. [Discount Function API](https://shopify.dev/docs/api/functions/latest/discount).

4. Обычное публичное приложение с Functions доступно на разных планах; собственное приложение с Shopify Function APIs требует **Shopify Plus**. Поэтому сначала уточнить тариф, затем выбрать подходящее приложение или заказную реализацию. Ничего не установлено. [Доступность Functions](https://shopify.dev/docs/apps/build/functions).

5. Ссылку на метаобъект в Liquid нельзя считать готовой конфигурацией Function. Для собственного приложения потребуется синхронизировать разрешённые профили, назначения product IDs и настройки дополнений в поддерживаемый вход/метаполя скидки либо читать подходящие серверные метаполя. Для готового приложения проверить поддержку именно такого подсчёта и сопоставить его правила с профилем темы; при необходимости адаптировать источник отображения. Не поддерживать две расходящиеся таблицы молча. Серверная классификация дополнительных вариантов обязательна: line item properties покупатель может изменить.

6. Shopify B2B также имеет quantity rules/volume pricing каталогов. Это отдельный режим с ценами/правилами вариантов; он не заменяет автоматически требуемую логику публичной корзины. Проверить применимость только если магазин действительно использует B2B-каталоги и согласованы покупатели/тариф. Не предполагать устаревшее общее ограничение B2B только планом Plus. [B2B quantity pricing](https://help.shopify.com/en/manual/b2b/catalogs/quantity-pricing), [возможности B2B по планам](https://help.shopify.com/en/manual/b2b/getting-started/features).

В теме подготовлены каталог профилей, таблица условий и подсчёт для подсказки. Shopify/app предстоит настроить применение скидок, даты, область действия, рынки/клиентов и совместимость. **Buy more, save more** включать только после совпадения профиля с проверенным серверным правилом. Корзина продолжает выводить `final_line_price`, `line_level_discount_allocations`, `cart_level_discount_applications` и `cart.total_price`, полученные от Shopify.

## Обновление корзины и сохранность покупки

`snippets/cart-content.liquid` — единый серверный источник строк, пустого состояния, скидок, итогов и офферов. Его используют `templates/cart.liquid` и существующая секция `cart-gift-offers`. `assets/cart.js` читает эту секцию через locale-aware URL корзины и обновляет только строки/итог/шаблон предложений. Живой `<dialog>` и обработчики не заменяются, прокрутка и фокус сохраняются. Счётчик берётся из `cart.item_count`, цены — из `variant.price | money`, `final_line_price`, discount allocations и `cart.total_price`. JavaScript не рассчитывает деньги. [Section Rendering API](https://shopify.dev/docs/api/ajax/section-rendering).

Перед открытием и каждым добавлением выполняется свежая проверка состава, доступности, цены и quantity rules. Изменившееся предложение требует повторного осознанного нажатия. Чужие изменения корзины применяются на месте, без отправки устаревшего выбора.

Один координатор блокирует конкурентные записи. Update отправляет только изменённые количества по **line keys**, Remove — ключ конкретной строки. `properties`, включая `Engraving text`, не перезаписываются, строки одного варианта с `Maya` и `Anna` не объединяются кодом темы. Нативная форма товара сохраняет и текстовые, и файловые свойства. Checkout передаёт все введённые количества штатным POST `/cart`, без ожидания таймера/GET офферов.

Сбой записи не считается доказательством отсутствия изменения: Shopify может изменить корзину даже при ошибке. Поэтому повторная запись разрешается после свежего чтения и проверки наличия варианта; при неудачном GET доступно **Refresh cart** и обычная ссылка **Reload cart**. Скрытого повтора POST и автоматического добавления платных товаров нет. [Cart API](https://shopify.dev/docs/api/ajax/reference/cart).

Без JavaScript основные Update/Remove/Checkout работают нативно. Постоянный блок с ценами виден, кнопки дополнений отключены и есть пояснение о JavaScript. Если браузер не поддерживает `showModal`, карточки блока работают, ручное/автоматическое окно недоступно. Остатки и окончательную цену всегда проверяет Shopify.

## Ручные проверки черновой темы

Локальные фикстуры не подтверждают реальную покупку, доступность вариантов в конкретном рынке, серверные скидки и свойства настоящего заказа. После отдельной загрузки в неопубликованную тему проверить:

1. Один основной товар и 2–4 назначенных оффера: видны максимум три, цены/валюта/фото реальны; на странице товара офферов нет. Несколько товаров с общим вариантом: одна карточка, порядок по строкам и назначениям, **Pairs with** с совместимой строкой.
2. Комплектации с коробкой и без: `true`, `false`, пустое значение, вариант false при товаре true; смешанная корзина. Коробка только для подходящего товара. Другие дополнения остаются.
3. Два разных дополнения последовательно, разные количества, двойное нажатие. Окно остаётся; Added совпадает в обоих местах; фактические строки, итог, скидки и счётчик обновляются без reload. Проверить прокрутку и фокус.
4. Уже добавленный вариант, sold out, выключенный оффер, персонализация, отсутствие фото, требуемая подписка, min > 1 и пустая корзина. Офферы не должны появляться от самих дополнений.
5. Новая вкладка: окно через 5 секунд; крестик/Escape/Continue, затем reload, возврат, Update, Remove — повторного автопоказа нет. Новая вкладка, открытая через дублирование, может наследовать sessionStorage браузера. Проверить запрет storage, выключение автопоказа и изменение задержки.
6. Начать Checkout до 5 секунд и во время проверки офферов: ни задержки, ни окна. Проверить скрытую вкладку, другой диалог (в том числе Forms), несохранённые количества.
7. Ошибка 422/403, обрыв сети/таймаут, частичный ответ и отказ секции. Added не появляется без подтверждения; после GET можно повторить, фактически присутствующее дополнение заблокировано. При недоступной сети — Refresh cart, затем восстановление и новая попытка.
8. Один вариант с `Maya` и `Anna`, прочими свойствами, спецсимволами и разными количествами: обновить одну строку, удалить другую, проверить 0 и Checkout. Надписи не смешиваются. Проверить обновление line keys после реальной скидки.
9. Мобильные Safari/Chrome, экранная клавиатура, 320/375/390 px и desktop: нет горизонтального переполнения; итог/Checkout доступны; окно внутри экрана, есть внутренняя прокрутка, крестик и Continue. Проверить Tab/Shift+Tab, возврат фокуса, фон, VoiceOver/NVDA. Локальная проверка Chromium не заменяет эти устройства/скринридеры.
10. На реальной черновой теме сопоставить cart и checkout по текущим скидкам, валютам/рынкам и количествам. Правила volume pricing этой задачей не менялись; прежние пороги N−1/N/N+1 остаются отдельной регрессией.
11. В Forms проверить отсутствие **Tailored corporate gift offers** на корзине и сохранность формы на согласованных страницах, полей и автоматизаций. Тема её глобально не скрывает.
12. Реальный заказ/оплата и проверка свойств в заказе выполняются отдельно по решению владельца; здесь их не было.
