# Офферы и скидки за количество — локальная подготовка

Дата: 15 ноября 2026. Изменена только локальная тема. Тема не загружалась и не публиковалась; Shopify Admin, товары, приложения, формы и действующие скидки не изменялись. Браузер и магазин для проверки не запускались.

Обновление 16 ноября: доработки объединены со свежим экспортом Shopify, последние картинки и тексты сохранены. [Актуальный ZIP и отчёт объединения](shopify-merge-2026-11-16.md).

Все три новых переключателя в **Theme settings → Gift offers & quantity savings** выключены по умолчанию. Реальных цен, variant ID, изображений и порогов в коде нет. Демонстрационные данные существуют только в offline-тесте `scripts/verify-gift-offers.cjs`, который не подключается к витрине.

## Что подготовлено

- На странице товара, перед покупкой: **Complete your gift**, явный выбор нескольких дополнений и отдельное количество каждого; **Buy more, save more** с утверждёнными процентными порогами общего профиля.
- В корзине: отдельное уведомление **Complete your gift** в обычном потоке над позициями, без фиксированного перекрытия Checkout; модальное окно с несколькими выбираемыми предложениями, их количеством и общей кнопкой **Add to cart**.
- Через 5 секунд после загрузки непустой корзины окно может открыться автоматически. Перед открытием тема получает свежую секцию через Shopify Section Rendering API и повторно проверяет состав корзины/предложения. Ручное открытие доступно после закрытия. Автоматический показ сохраняется в `sessionStorage` один раз за сессию вкладки, включая перезагрузки. Если хранилище недоступно, работает только ручное открытие.
- Окно не открывается автоматически поверх другого native dialog, в скрытой вкладке, во время изменения корзины или при несохранённых количествах. Для ручного открытия при несохранённых количествах предлагается сначала **Update cart**. Пропущенный автоматический показ не перезапускается при пересчётах этой страницы.
- Нативный `<dialog>` обеспечивает Escape и изоляцию фокуса; предусмотрены крестик, циклический Tab/Shift+Tab и возврат фокуса. Реальное поведение браузеров/скринридеров ещё требует проверки.
- Из всех основных строк собираются доступные офферы. Один продаваемый вариант отображается один раз с перечнем **Pairs with**. Если несколько записей оффера ссылаются на один вариант, первое подходящее предложение определяет название/фото. Уже присутствующий в корзине вариант дополнения повторно не предлагается: его количество меняют в самой корзине.
- Нет автоматического соответствия «одна коробка на каждую ручку»: количество дополнений выбирает покупатель, независимо от количества основного товара. Для товара с коробкой исключается именно предложение типа `gift_box`; иные дополнения остаются доступны.

## Модель данных

Общий каталог — небольшой метаобъект **Gift offer**. Он содержит ссылку на реальный вариант Shopify и настройки показа, но не собственную цену. Одну запись можно выбирать у нескольких основных товаров и менять централизованно. Список ссылок у товара определяет порядок. Отдельная админка и приложение для офферов не нужны.

Одних ссылок на товары недостаточно для выбора конкретного продаваемого варианта. Вариант как единственный объект оффера потребовал бы размещать редакционные настройки каждого предложения на вариантах. Метаобъект оставляет каталог предложений в **Content → Metaobjects**, а склад и цену — у продаваемого варианта. Используются стандартные [типы данных Shopify](https://shopify.dev/docs/apps/build/metafields/list-of-data-types) и [списки ссылок](https://help.shopify.com/en/manual/custom-data/metafields/metafield-definitions/metafield-lists).

### 1. Метаобъект Gift offer

В **Settings → Custom data → Metaobjects → Add definition** создать тип `elma_gift_offer`. Включить доступ для витрины; если используется возможность Draft/Active, публиковать только готовые записи. Создание отдельных веб-страниц для записей не требуется.

| Ключ поля | Тип | Настройка / источник |
| --- | --- | --- |
| `title` | `single_line_text_field` | Название предложения, например согласованное название коробки; использовать как display name. Пустое значение имеет fallback на название товара. |
| `variant` | `variant_reference` | Обязательная ссылка на конкретный продаваемый вариант. Выбирать через Shopify picker, не вводить ID в код темы. |
| `image` | `file_reference`, только изображения | Необязательное фото оффера; fallback: фото варианта, затем товара. При отсутствии всех фото оффер скрыт. |
| `enabled` | `boolean` | Только `true` разрешает предложение. Пустое/false скрывает его у всех товаров. |
| `kind` | `single_line_text_field`, choices | Только `gift_box` или `other`. Пустое/неизвестное значение скрывает оффер. |

**Поля цены нет.** На витрине выводится `offer.variant.value.price | money`, а покупка идёт через `/cart/add.js` с настоящим variant ID. JavaScript не передаёт цену. Налоги, скидки и итоговые суммы остаются за Shopify. Поле `_elma_gift_offer` — скрытая метка роли строки, не доплата и не источник права на скидку.

### 2. Метаполя товаров и вариантов

Создать определения в **Settings → Custom data → Products / Variants** с доступом для витрины.

| Владелец | Namespace/key | Тип | Назначение |
| --- | --- | --- | --- |
| Product | `custom.gift_offers` | `list.metaobject_reference` → `elma_gift_offer` | Выбрать несколько общих офферов. Порядок значений — порядок на товаре. Для начала держать список компактным. |
| Product | `custom.includes_gift_box` | `boolean` | Необязательный общий ответ для всех комплектаций товара. |
| Variant | `custom.includes_gift_box` | `boolean` | Приоритет над значением товара. `true` — коробка входит; `false` — не входит. Если оба значения не заполнены, коробка не предлагается. Нельзя определять комплектацию по словам в названии. |
| Variant | `custom.is_gift_addon` | `boolean` | У продаваемого варианта дополнения обязательно `true`, иначе быстрый оффер скрыт. Такой вариант не считается основным при подсчёте количества и не порождает дальнейшие офферы. |
| Variant | `custom.requires_personalization` | `boolean` | `true` исключает вариант из быстрого добавления при любых прочих настройках. Использовать для сценариев, ещё не описанных текущими полями гравировки. |
| Product | `custom.volume_profile` | `metaobject_reference` → `elma_volume_profile` | Один общий профиль скидок; несколько товаров могут ссылаться на одну запись. |

Существующие `custom.personalization_enabled`, `personalization_required`, `personalization_max_length`, `personalization_no_engraving_values` не переименовывать. Дополнение с включённой или обязательной персонализацией исключается, кроме явно распознанного существующим механизмом варианта **No engraving**. `custom.requires_personalization = true` исключает его и в этом случае. Перед включением оффера проверить, что для него не нужны другие обязательные поля, загрузки, планы подписки или отдельная настройка комплекта. Продукты с обязательной подпиской исключены.

Для первой коробки: выбрать/подготовить настоящий товар, цену, фото, склад, доставку и продаваемый вариант, опубликованный в Online Store и нужных рынках. У варианта поставить `is_gift_addon = true`. Создать одну запись `Gift offer` с `kind = gift_box`. Подключить её через `custom.gift_offers` к нужным основным товарам и явно заполнить сведения о комплектации. Все эти действия — будущий этап, сейчас ничего не создано.

Для второй ручки или другого дополнения применяется тот же каталог. Если ручка должна также продаваться как основной товар со скидкой, использовать **отдельный реальный вариант/товар для роли дополнения**: один и тот же variant ID нельзя надёжно считать то основным, то дополнением только по изменяемому свойству браузера. Согласовать складской учёт. Пока у дополнения нужна гравировка, быстрый оффер останется скрытым; отдельный сценарий персонализации потребуется позже.

### 3. Метаобъект Volume profile

Создать тип `elma_volume_profile`, разрешить доступ для витрины. Поля:

| Ключ | Тип | Назначение |
| --- | --- | --- |
| `title` | `single_line_text_field` | Название профиля для выбора в Admin; display name. |
| `enabled` | `boolean` | Оставить false до настройки и проверки настоящих скидок. Это переключатель отображения, он не активирует скидку Shopify. |
| `tiers` | `json` | Массив объектов с ключами `minimum` и `percent_off`. Пока нет утверждения — `[]`. |

У `minimum` должно быть положительное целое число; у `percent_off` — число больше 0 и меньше 100. Пороги и проценты должны строго возрастать. Строки вместо чисел, пустой массив, некорректный порядок или значения скрывают весь блок. Реальных или демонстрационных порогов в тему не встроено. Процентный профиль выбран, чтобы разные цены вариантов и валюты не требовали ручных таблиц фиксированных сумм.

Подсчёт: сумма количеств строк **одного product ID** с любой гравировкой и основными вариантами этого товара. `Maya × 1` + `Anna × 2` дают 3 единицы, но остаются двумя строками. Другой товар с тем же профилем начинает свой подсчёт отдельно. Варианты `is_gift_addon = true` и строки с `_elma_gift_offer = true` исключаются. На странице товара подсвечивается порог для уже имеющегося количества плюс вводимое количество. Это подсказка по снимку корзины при загрузке страницы; она не подтверждает скидку и не меняет цены.

## Реальное применение скидок — следующий этап

Справка проверена по официальной документации 15 ноября 2026. Тариф и действующие скидки конкретного магазина не запрашивались.

1. **Небольшой набор товаров и порогов:** можно использовать автоматические **Amount off products → Percentage**, отдельную скидку на каждый порог одного основного товара, с **Minimum quantity of items**. Только выбранные товары/варианты должны входить в подсчёт. Не объединять разные основные товары в одну область действия, если порог должен считаться по каждому product ID отдельно. Добавляемые коробки и другие дополнительные варианты исключить. Это кандидат для простого запуска, который нужно проверить на двух строках с разной гравировкой. [Минимальные требования и области действия](https://help.shopify.com/en/manual/discounts/discount-types/percentage-fixed-amount).

2. Пороговые скидки одного товара не должны складываться на одной строке. Для разных товаров и других текущих скидок отдельно согласовать правила сочетания и проверить выбор лучшей скидки. Shopify допускает **до 25 активных автоматических скидок**, включая приложения; схема «товары × пороги» быстро расходует лимит. Не менять существующие скидки ради освобождения лимита автоматически. [Сочетание и лимиты скидок](https://help.shopify.com/en/manual/discounts/discount-combinations).

3. **Много товаров, общий профиль и независимый подсчёт каждого товара:** предпочтительна одна скидка приложения на **Discount Function API**. Алгоритм: прочитать cart lines, product/variant IDs и серверные признаки дополнений; сгруппировать только основные строки по product ID; выбрать максимальный достигнутый порог профиля; применить процент ко всем подходящим cart line IDs этого товара. Не изменять и не объединять строки с надписями. При уменьшении количества Shopify должен пересчитать скидку. Function работает в серверном расчёте; тема этого сделать не может. [Discount Function API](https://shopify.dev/docs/api/functions/latest/discount).

4. Обычное публичное приложение с Functions доступно на разных планах; собственное приложение с Shopify Function APIs требует **Shopify Plus**. Поэтому сначала уточнить тариф, затем выбрать подходящее приложение или заказную реализацию. Ничего не установлено. [Доступность Functions](https://shopify.dev/docs/apps/build/functions).

5. Ссылку на метаобъект в Liquid нельзя считать готовой конфигурацией Function. Для собственного приложения потребуется синхронизировать разрешённые профили, назначения product IDs и настройки дополнений в поддерживаемый вход/метаполя скидки либо читать подходящие серверные метаполя. Для готового приложения проверить поддержку именно такого подсчёта и сопоставить его правила с профилем темы; при необходимости адаптировать источник отображения. Не поддерживать две расходящиеся таблицы молча. Серверная классификация дополнительных вариантов обязательна: line item properties покупатель может изменить.

6. Shopify B2B также имеет quantity rules/volume pricing каталогов. Это отдельный режим с ценами/правилами вариантов; он не заменяет автоматически требуемую логику публичной корзины. Проверить применимость только если магазин действительно использует B2B-каталоги и согласованы покупатели/тариф. Не предполагать устаревшее общее ограничение B2B только планом Plus. [B2B quantity pricing](https://help.shopify.com/en/manual/b2b/catalogs/quantity-pricing), [возможности B2B по планам](https://help.shopify.com/en/manual/b2b/getting-started/features).

В теме подготовлены каталог профилей, таблица условий и подсчёт для подсказки. Shopify/app предстоит настроить применение скидок, даты, область действия, рынки/клиентов и совместимость. **Buy more, save more** включать только после совпадения профиля с проверенным серверным правилом. Корзина продолжает выводить `final_line_price`, `line_level_discount_allocations`, `cart_level_discount_applications` и `cart.total_price`, полученные от Shopify.

## Существующая форма Tailored corporate gift offers

Локально подтверждены включённый Forms app embed в `config/settings_data.json`, `content_for_header` в layout и прежние `bonus-popup.css` / `bonus-popup.js`. Последние содержат стили/обработку контейнера `app-embed-container-1210851`; историческая инструкция связывает его с попапом **1210851**. Inline quote form **1155185** подключена отдельно. Само содержимое, текущий teaser, правила Pages/Trigger и автоматизации попапа из темы прочитать нельзя. Текущий ID и название нужно сверить в Admin; исторические наблюдения не являются проверкой работающего магазина сегодня.

Код, стили, embed и существующие inline-блоки форм оставлены без изменений. Новый компонент не обращается к DOM Shopify Forms и не переносит/скрывает его.

Будущая последовательность в **Apps → Forms**:

1. Найти существующую форму по текущему уведомлению **Tailored corporate gift offers**, сверить ID. Зафиксировать текущие поля, content, success, обработку заявок, уведомления, теги, согласие и связанные автоматизации.
2. В **Behavior → Pages** проверить реальные возможности настройки. Официальная справка описывает **all pages / specific page types**, например Collection или Product; выбор точного URL ею не подтверждён. [Настройки popup-форм](https://help.shopify.com/en/manual/promoting-marketing/create-marketing/forms-app/settings/popup).
3. Если в текущем интерфейсе есть правило точного URL, выбрать `/collections/all`, учесть локализованные пути и исключить корзину. Если есть только типы страниц, стандартный ближайший вариант — **Collection pages**, который охватывает все коллекции, а не только `/collections/all`. Зафиксировать это ограничение; если строго необходим единственный URL, сначала согласовать дальнейший шаг с владельцем/поддержкой Shopify Forms. Обходной CSS/JS не внедрять.
4. Проверить отсутствие старого уведомления и окна на `/cart`, наличие на согласованных страницах каталога. Содержимое, поля, отправку, обработку и автоматизации сохранить. Глобальный app embed не отключать.
5. Только после этого разрешить **Enable cart gift offers** в черновой теме. Настройки Forms относятся к приложению/магазину и не изолируются просто выбором черновой темы; этап настройки нужно выполнять осознанно отдельно.

## Поведение корзины и границы

- `assets/commerce.js` расширяет единственный обработчик формы товара. При выбранных офферах отправляется один запрос `items` с основным вариантом, его количеством, всеми текстовыми `properties[...]` и выбранными дополнениями. При отсутствии дополнений остаётся нативная отправка. Поле-файл в свойствах не отбрасывается: комбинированное добавление останавливается с предложением сначала добавить основной товар отдельно.
- Запись выполняет `assets/cart.js` с общей блокировкой для товара, офферов, удаления, Update и Checkout. Изменение/удаление существующих строк остаётся по line item key. Количества не заменяют свойства строк.
- Перед добавлением из модального окна заново проверяются секция, наличие офферов, цена и quantity rules. Изменённое предложение надо выбрать снова. При изменении корзины в другой вкладке выполняется GET-переход в актуальную корзину вместо отправки старых количеств.
- После успешного добавления перечитывается `/cart.js`, обновляется счётчик и выполняется GET-переход в корзину для серверных сумм. Нет локального пересчёта списываемых денег, изменения Checkout или фиктивного сообщения об успехе.
- При 403/422, таймауте, сетевой ошибке или неизвестном ответе покупатель должен **Review cart / Reload cart**. Повторная запись и Checkout блокируются до свежей страницы. Shopify может частично изменить корзину даже при 422, поэтому автоматического повтора, отката или обещания «ничего не добавлено» после записи нет. [Cart API и ошибки](https://shopify.dev/docs/api/ajax/reference/cart).
- GET секции может вернуть `null` даже с HTTP 200: окно тогда не открывается. [Section Rendering API](https://shopify.dev/docs/api/ajax/section-rendering).
- Без JavaScript офферы скрыты, основная покупка и штатные поля сохраняют нативный сценарий. В браузере без `dialog.showModal` новый компонент корзины не показывается. Обновление офферов при переключении варианта использует конфигурацию со времени загрузки; окончательную возможность покупки всегда определяет Shopify. Проверки не заменяют серверную валидацию.

## Что нужно получить от команды

- Коробка: конкретный товар/вариант, утверждённая цена в Shopify, фото, название, доступные рынки, остатки/политика продажи и доставка.
- Какие комплектации уже содержат коробку; где она точно не входит. Карта основных товаров → список и порядок офферов.
- Второе и последующие дополнения: какие варианты, нужна ли персонализация, отдельный вариант для роли дополнения и правила складского учёта.
- Профили: утверждённые пороги/проценты, назначенные товары; подтверждение суммирования вариантов одного товара и независимого подсчёта разных товаров.
- Тариф магазина, действующие автоматические скидки/коды, правила сочетания, даты, рынки и категории покупателей.
- Для Forms: допустимы ли все страницы коллекций, если конкретный URL недоступен; проверка текущей формы/автоматизаций в Admin.

## Чек-лист черновой темы на следующем этапе

1. Сверить свежую тему магазина и локальные изменения, перенести доработку в неопубликованную копию отдельной командой. Не перезаписывать текущую тему целиком старым экспортом. Сначала оставить все новые переключатели false.
2. Создать определения и записи из этой инструкции. Без записей, с false/Draft, недоступным/удалённым вариантом, без фото или с обязательной персонализацией блоки должны скрываться. Проверить разные рынки/валюты и реальный остаток.
3. Подключить коробку и ещё одно дополнение к двум основным товарам. Проверить порядок, общий каталог, смену фото/названия/цены в одном месте. Проверить `includes_gift_box = true / false / пусто`, приоритет варианта над товаром, очистку выбора коробки при переключении комплектации.
4. Добавить основной товар без офферов, затем с одним и несколькими выбранными офферами. Проверить выбранный вариант, количества, `Maya`, `Anna`, дополнительные свойства, спецсимволы. Ни одно неотмеченное дополнение не должно добавиться.
5. Проверить минимум/шаг/максимум количества дополнения, sold out между просмотром и нажатием, смену цены, двойное нажатие, 422/403/таймаут. После ошибки проверить фактическую корзину перед повтором; не считать запрос атомарным.
6. В корзине: Maya и Anna остаются отдельными строками; Update, Remove, 0, счётчик, суммы Shopify, discounts и Checkout сохраняются. Проверить Back/Forward, перезагрузку и изменение из другой вкладки.
7. Пустая корзина/нет офферов → нет уведомления и окна. Несколько основных товаров → одно предложение на продаваемый вариант, понятный **Pairs with**. Уже купленное дополнение не предлагается снова. Коробка не предлагается для комплекта с включённой коробкой.
8. Новая сессия вкладки: окно через 5 секунд; закрытие → не открывается автоматически после reload/Update/Remove. Ручное открытие работает. Проверить запрет sessionStorage, медленную сеть, пустой/`null` ответ секции, изменение количества до таймера.
9. Телефон 320/375/390 px и desktop: Checkout не перекрыт уведомлением, длинные названия/списки помещаются, модальное окно прокручивается. Крестик, Escape, Tab, Shift+Tab, фокус после закрытия, экранная клавиатура и скринридер. Браузерные проверки здесь ещё не выполнялись.
10. Настроить настоящую скидку отдельным этапом. Проверить порог N−1/N/N+1, Maya+Anna, два разных варианта того же продукта, другой товар с тем же профилем, коробки/дополнения, уменьшение количества, сочетание с существующим кодом, разные валюты. Суммы в cart и checkout должны совпадать с правилами Shopify. Только после этого включить `profile.enabled` и **Show quantity savings profiles**.
11. Отдельно выполнить перенос правил показа существующей Forms по инструкции выше, затем включить **Enable cart gift offers**. Убедиться, что два уведомления в корзине не конкурируют.
12. Проверить текст гравировки и цены в checkout. Реальный тестовый заказ и его оплата — только по отдельному решению; это не выполнено и не подтверждено локальными тестами.
